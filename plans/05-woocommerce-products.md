# План: Лайк/дизлайк на товарах WooCommerce

## Мета
Дозволити показувати кнопки лайк/дизлайк на сторінках товарів WooCommerce, розширивши список "Where to display?".

## Чому це відносно дешево реалізувати
Лічильники `counter_like`/`counter_dislike` вже зберігаються прямо в колонках `wp_posts` — а товар WooCommerce **це теж запис у `wp_posts`** (post_type = `product`). Тобто рушій зберігання **не треба міняти взагалі** — досить розширити умови показу (`$should_display` bitwise-перевірки в `front-likes.php`) новим бітом і новою WP-умовою `is_product()`.

## Обов'язкова умова: сайт без WooCommerce не повинен ламатись
На цьому сайті (`deposit-statistics.local`) WooCommerce **зараз не встановлено** — перевірено, плагіна нема в `wp-content/plugins`. План має:
- Обгортати всі WooCommerce-специфічні хуки/функції в `if (class_exists('WooCommerce'))`, щоб при відсутньому WooCommerce нічого не ламалось і не з'являлось зайвих PHP-помилок (`is_product()` не існує без WC).
- Чекбокс "Products" у налаштуваннях показувати завжди, але він просто нічого не робить, якщо WooCommerce не активний (не приховувати опцію — сайт може встановити WC пізніше).
- Тестування вимагатиме встановити WooCommerce на дев-сайт локально (просте `wp plugin install woocommerce --activate` через WP-CLI, або через адмінку).

## Зміни в БД
Новий біт для `display` (bitmask, зараз зайняті: 1=Homepage, 2=Pages, 4=Posts, 8=Comments, 16=Archive) → **32 = Products**. Змін схеми не треба — колонка `display` вже INT, витримує додатковий біт.

## Зміни в коді
1. **`index.php`** — новий чекбокс у "Where to display?":
   ```php
   <label class="plb-check"><input type="checkbox" name="display[]" <?php echo @$display['32']; ?> value="32"><?php _e('Products', 'prolike');?></label>
   ```
   + `if ($myrows[0]->display & 32) { $display[32] = 'checked'; }` у блоці читання.
2. **`front-likes.php`** (`plb_pro_like_button`) — додати перевірку:
   ```php
   if (($display & 32) && function_exists('is_product') && is_product()) {
       $should_display = true;
   }
   ```
3. Шорткод `[prolikebutton_shortcode]` вже працює на будь-якому post ID — на сторінці товару спрацює без змін, якщо тема сама викликає `do_shortcode()` (як зараз зроблено в темі для постів) або якщо увімкнено `the_content` filter (тоді кнопки автоматично з'являться в описі товару).

## Опціонально (друга ітерація, не MVP)
- Показ кнопок і в архіві товарів (сторінка магазину/категорії) — окремий підпункт "Products archive", бо там компактний вигляд потрібен інакший (менший розмір кнопки, без лічильника тексту).
- Хук `woocommerce_after_single_product_summary` для автоматичної вставки під описом товару (зараз кнопки вставляються через `the_content`-фільтр або шорткод — опис товару теж проходить через `the_content`, тож це, ймовірно, вже спрацює без додаткового хука; перевірити на практиці).

## Файли, які будуть змінені
- `index.php` — новий чекбокс + читання біта 32.
- `front-likes.php` — нова умова в `$should_display`.

## Тестування
- Встановити WooCommerce на `deposit-statistics.local` (наразі не встановлений).
- Створити тестовий товар, увімкнути чекбокс "Products", перевірити появу кнопок на сторінці товару.
- Перевірити, що сайти БЕЗ WooCommerce не отримують жодних PHP-помилок (fatal error на `is_product()` якщо забути `function_exists()`-перевірку — це найкритичніша точка).
- Перевірити лічильники лайків окремо від лічильників звичайних постів — не повинні змішуватись (вони й не змішаються, бо прив'язані до конкретного post ID товару).
