# План: Дашборд статистики голосів

## Мета
Окремий екран в адмінці плагіна з підсумками: скільки лайків/дизлайків усього, скільки сьогодні/цього тижня, і список найпопулярніших постів/коментарів — без ручного сортування списку постів.

## Чому зараз це неможливо зробити "дешево"
Плагін зберігає лише **агреговані лічильники** (`counter_like`/`counter_dislike` колонки прямо в `wp_posts`/`wp_comments`). Немає історії голосів у часі — тому "скільки голосів сьогодні" чи "за цей тиждень" порахувати неможливо без окремого логу подій.

## Зміни в БД
Нова таблиця `wp_prolike_votes`:
| колонка | тип | опис |
|---|---|---|
| id | BIGINT AUTO_INCREMENT PK | |
| object_type | VARCHAR(10) | `post` \| `comment` |
| object_id | BIGINT | ID поста/коментаря |
| vote_type | VARCHAR(10) | `like` \| `dislike` |
| user_id | BIGINT NULL | якщо залогінений |
| ip_hash | VARCHAR(64) NULL | `hash('sha256', IP . SALT)`, не сира IP |
| created_at | DATETIME | |

Індекси: `(object_type, object_id)`, `(created_at)`.

Міграція через уже наявний `plb_maybe_upgrade_db()` — підняти `PLB_DB_VERSION`, додати `CREATE TABLE IF NOT EXISTS`.

## Зміни в коді
1. **`include/enqueue-front.php`** (`plb_action_callback`) — після успішного лайку/дизлайку додатково писати рядок у `wp_prolike_votes` (INSERT, не зачіпає існуючу логіку лічильників).
2. **Нова admin-сторінка** `plb_stats_page()`, підключена через `add_submenu_page('prolike_first_plugin', 'Statistics', 'Statistics', 'manage_options', 'prolike_stats', 'plb_stats_page')`.
3. **Запити для дашборду:**
   - Всього лайків/дизлайків: `SUM(counter_like)`, `SUM(counter_dislike)` з `wp_posts`.
   - Сьогодні: `COUNT(*) FROM wp_prolike_votes WHERE DATE(created_at) = CURDATE()`.
   - Цей тиждень vs минулий (для % росту): два `COUNT` з `WHERE created_at >= ...`.
   - Топ-10 постів: `ORDER BY counter_like DESC LIMIT 10` (уже є в `wp_posts`, без join).
4. **UI:** переставити дизайн-систему з `admin.css` (`.plb-card`/`.plb-row`) — картки з цифрами зверху + таблиця "Топ постів" знизу, посилання на edit/view кожного поста.

## Файли, які будуть змінені
- `index.php` (реєстрація нової сторінки, upgrade-міграція)
- `include/enqueue-front.php` (запис у лог)
- новий `include/stats-page.php`
- `assets/css/admin.css` (стилі карток статистики)

## Тестування
- Перевірити, що лог пишеться при кожному лайку/дизлайку (post і comment).
- Перевірити коректність "сьогодні"/"цей тиждень" на межі опівночі (часовий пояс WP, не сервера — `current_time('mysql')`).
- Навантаження: таблиця голосів росте необмежено — варто одразу подумати про очищення старих записів (наприклад, зберігати детальний лог лише за останні 90 днів, а старіше — агрегувати в денну зведену таблицю). Це можна залишити на друге ітерацію, не MVP.
