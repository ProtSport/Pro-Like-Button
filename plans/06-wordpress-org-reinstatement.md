# План: відновлення Pro Like Button у каталозі WordPress.org

## Нагадування, чому плагін зняли
Лист від security-команди WordPress.org: неавтентифікована SQL-ін'єкція в `wp_ajax_nopriv_id` (AJAX-обробнику лайків) — `postid` підставлявся напряму в SQL без `$wpdb->prepare()`. Репортери: Enrico Marcolini, Claudio Marchesini, Dottor Marc (через WPScan). Лістинг **тимчасово** прихований, не видалений — відновлюється після повторного рев'ю.

## Статус: що вже зроблено в цій сесії
- [x] SQL-ін'єкцію виправлено — `postid` через `absint()` + `$wpdb->prepare()` з `%d` у всіх запитах.
- [x] Версію піднято (1.0.4 → 1.0.5, і код з того часу пішов далі, зараз фактично готовий на 1.1.0 — див. нижче).
- [x] Виправлено кілька PHP Warning'ів (activation, save-форма, `posts_clauses`) — на PHP 8+ такі попередження самі по собі є приводом для зауважень при ре-рев'ю.
- [x] Виправлено "Array to string conversion" у шорткод-обробнику.
- [x] Додано `readme.txt` changelog-запис з подякою репортерам вразливості.

## Що ще НЕ зроблено (обов'язково перед відправкою)

### 1. Прогнати Plugin Check
Встановити на dev-сайт офіційний [Plugin Check](https://wordpress.org/plugins/plugin-check/) і прогнати проти `like-button-pro`. Очікувані типи зауважень (з опису листа — "we expect all issues detected by Plugin Check Plugin will be resolved"):
- Інші `$wpdb->query()`/`get_row()` з інтерпольованими змінними без `prepare()` — у `front-likes.php`, `admin_post_field.php`, `include/stats-page.php`, `include/schema.php` (там де це `$table`/`$id_column` — самі назви таблиць/колонок, не користувацький ввід, але Plugin Check однаково їх підсвітить; треба або `phpcs:ignore` коментар з поясненням, або обгорнути через `%i`/backticks там, де можливо).
- Текстовий домен: у коді впереміш використовуються `'prolike'`, `'prolikebutton'` і заголовок плагіна "Pro Like Button" — Plugin Check вимагає **один** консистентний text domain, що збігається зі слагом плагіна (`prolike-button`). Це варто уніфікувати перед відправкою.
- `readme.txt`: version WordPress "Tested up to" — я поставив `6.6` орієнтовно, звірте з актуальною версією на [wordpress.org/download/releases](https://wordpress.org/download/releases/) на момент відправки.
- Відсутність `index.php` (silence is golden) у деяких піддиректоріях (`plans/`, `assets/img/icon_button/` тощо) — Plugin Check і WP.org review іноді відзначають директорії без заглушки; для `plans/` це взагалі не має потрапити в SVN (див. нижче).

### 2. Не заливати `plans/` у SVN
Папка `plans/` (внутрішні нотатки розробки, які ми зараз пишемо) — це не частина плагіна для кінцевих користувачів. Перед комітом у SVN:
- Або додати `plans/` у `.svnignore`/просто не `svn add` цю директорію,
- Або тримати її лише в git-репозиторії (GitHub), не копіюючи в SVN checkout взагалі.

### 3. Підняти версію ще раз, осмислено
З часу 1.0.5 додано: Statistics-дашборд, rate-limiting, reCAPTCHA, structured data, WooCommerce-підтримка, повний редизайн адмінки. Це не патч-реліз — за semver це щонайменше **1.1.0** (нова функціональність, зворотна сумісність збережена). Оновити:
- `@version` та `Version:` у шапці `index.php`.
- `Stable tag:` у `readme.txt`.
- Додати повний changelog-запис з переліком нових фіч (для користувачів, які читають readme на сторінці плагіна).

### 4. Комерційно-технічна перевірка SVN-доступу
- Переконатись, що є доступ до `https://plugins.svn.wordpress.org/prolike-button/` (той самий акаунт wordpress.org, яким плагін було опубліковано раніше — не плутати з GitHub-акаунтом ProtSport, це окремий логін).
- Структура SVN: `trunk/` — поточна версія (те, що бачать користувачі), `tags/1.1.0/` — незмінний знімок релізу, `assets/` — банер/іконка/скріншоти плагіна на сторінці wordpress.org (не плутати з `wp-content/plugins/.../assets/` усередині самого плагіна — це різні речі).

### 5. Синхронізувати git → SVN
Практичний порядок дій (без git-SVN мостів, вручну — простіше і безпечніше для такого розміру плагіна):
1. `svn checkout https://plugins.svn.wordpress.org/prolike-button/ prolike-button-svn`
2. Скопіювати актуальний вміст плагіна (без `.git/`, без `plans/`) у `prolike-button-svn/trunk/`.
3. `svn add` нові файли, `svn status` — звірити, що нічого зайвого не потрапило.
4. `svn cp trunk tags/1.1.0` (тег версії).
5. `svn commit -m "1.1.0: security fix (SQL injection), new anti-spam and stats features"`.

### 6. Відповісти на лист security-команди
Після коміту в SVN — відповісти на оригінальний лист (реплаєм, вони самі про це просили: "Reply to this email to request a re-review"). У відповіді коротко:
- Що саме виправлено (validated integer + prepared statements для `postid`).
- Що зроблено додатково понад мінімум (Plugin Check пройдено, повний рев'ю коду).
- Посилання на конкретний коміт/тег у SVN.
- Подяка репортерам вже в changelog (можна це теж згадати).

### 7. Очікування щодо таймінгу
- Лист попереджав: **вони перевірять весь плагін заново**, не тільки цю функцію — якщо Plugin Check чи ручний рев'ю знайде щось ще, доведеться виправляти й це перед повторним відкриттям. Закладіть час на 1–2 раунди зауважень.
- Лічильник "60 днів до публічного розкриття причини закриття" — наскільки я розумію з контексту цієї розмови, ще не спливає найближчим часом, але краще не затягувати.
