# План: reCAPTCHA + Rate-limiting (захист від накрутки голосів)

## Мета
Зупинити накрутку лайків/дизлайків скриптом: зараз `plb_action_callback` (AJAX-обробник) приймає голоси без жодного обмеження частоти — nonce перевіряє лише "запит прийшов з нашої сторінки", а не "скільки разів".

## Важливий нюанс (див. обговорення офісної IP)
IP **не використовується** як єдиний блокувальний фільтр (в офісі/за NAT одна IP на багатьох людей). IP йде лише в **rate-limiting** ("не більше N запитів з однієї IP за хвилину"), а не в "один голос на IP назавжди" — це лишається на cookie/user_id, як і зараз.

## Частина 1 — Rate-limiting (без зовнішніх залежностей, MVP)
- Використати WP transients як лічильник: ключ `plb_rl_{ip_hash}`, TTL 60 секунд.
- У `plb_action_callback`, на самому початку (до будь-яких SQL-запитів):
  ```php
  $ip_hash = hash('sha256', $_SERVER['REMOTE_ADDR'] . wp_salt());
  $key = 'plb_rl_' . $ip_hash;
  $count = (int) get_transient($key);
  if ($count >= $limit_per_minute) {
      wp_die(); // або wp_send_json_error з кодом 429
  }
  set_transient($key, $count + 1, 60);
  ```
- Ліміт (`$limit_per_minute`) — налаштування в адмінці, дефолт наприклад 10 голосів/хв з однієї IP.
- Додатково опційно: денний ліміт з однієї IP (наприклад 200/добу) — той самий механізм з TTL 86400.

## Частина 2 — reCAPTCHA (опційно, вимикається за замовчуванням)
Плагін не повинен ламати голосування для сайтів, які не налаштували ключі — тому reCAPTCHA працює лише якщо в налаштуваннях вписані Site Key + Secret Key.

### Вибір версії
Новий select у налаштуваннях: **None (default) / v2 Checkbox / v3 Invisible**.

- **v2** — класичний чекбокс "Я не робот", показується перед голосуванням (модальне вікно або inline). Простіше в реалізації, помітне для користувача.
- **v3** — невидимий, оцінює score 0.0–1.0 без взаємодії користувача. Потрібен поріг (`threshold`, дефолт 0.5) — нижче порогу голос відхиляється. Менш нав'язливо для UX, складніше налаштувати правильний поріг.

Рекомендація: почати з **v3** як основного варіанта (не заважає однокліковому лайку, що є суттю фічі), v2 — як запасний варіант для сайтів, де v3 дає забагато false positives.

### Реалізація
1. **Налаштування** (нова секція в General або окрема вкладка "Anti-spam"):
   - `recaptcha_version`: none / v2 / v3
   - `recaptcha_site_key`, `recaptcha_secret_key`
   - `recaptcha_v3_threshold` (float, 0–1)
2. **Front-end** (`assets/js/like_click.js` + `front-likes.php`):
   - Якщо версія задана — підключити `https://www.google.com/recaptcha/api.js` умовно (тільки коли ключі заповнені).
   - v3: отримати токен через `grecaptcha.execute(siteKey, {action: 'plb_vote'})` перед AJAX-запитом, додати `recaptcha_token` в POST.
   - v2: показати чекбокс, заблокувати кнопку лайку, поки чекбокс не пройдено.
3. **Сервер** (`plb_action_callback`):
   - Якщо reCAPTCHA увімкнена — верифікувати токен через `wp_remote_post('https://www.google.com/recaptcha/api/siteverify', ...)` з secret key.
   - v3: перевірити `response.score >= threshold`.
   - Якщо перевірка не пройшла — `wp_die()`, голос не рахується.

## Файли, які будуть змінені
- `index.php` — нові поля налаштувань (Anti-spam секція), збереження в `$data1`.
- БД — нові колонки в `wp_prolike`: `recaptcha_version`, `recaptcha_site_key`, `recaptcha_secret_key`, `recaptcha_threshold`, `rate_limit_per_minute` (через `plb_maybe_upgrade_db`).
- `include/enqueue-front.php` — rate-limit перевірка + reCAPTCHA верифікація в `plb_action_callback`.
- `front-likes.php` — умовне підключення recaptcha.js, генерація токена перед AJAX-запитом.
- `assets/js/like_click.js` — відправка токена разом з голосом.

## Тестування
- Голосування без reCAPTCHA (дефолт) — має працювати як зараз, без регресій.
- Перевищення rate-limit — перевірити, що 11-й запит за хвилину з тієї ж IP відхиляється, а 61-та секунда — знову дозволяє.
- reCAPTCHA v3 з навмисно низьким score (тест-ключі Google для форсування fail) — голос не рахується.
- Сайт без інтернет-доступу до Google (заблокований в деяких країнах) — переконатись, що це не блокує ВЕСЬ функціонал лайків, а тільки reCAPTCHA-частину (graceful fallback).

## Відкриті питання

- Чи потрібен білий список IP (наприклад, для власного офісу/тестування) для rate-limiting?
